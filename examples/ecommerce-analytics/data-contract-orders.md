## Schema

## Freshness SLA

- **Update frequency:** Daily
- **Availability time:** Data for day D available by **07:00 BRT on D+1**
- **Maximum delay tolerance:** 1 hour (data available by 08:00 BRT at most)
- **How to measure:** `MAX(order_date) = CURRENT_DATE - 1` and `MAX(_processed_at) < CURRENT_TIMESTAMP() - INTERVAL 20 HOUR`
- **Alert configured:** Dagster SLA alert → #data-platform on Slack if pipeline does not complete by 06:30

## Quality Expectations

### Completeness

| Column | Rule | Threshold |
|--------|------|-----------|
| order_id | Never null | 100% |
| customer_id | Never null | 100% |
| order_date | Never null | 100% |
| order_status | Never null | 100% |
| order_amount_brl | Never null | 100% |
| net_revenue_brl | Never null | 100% |

### Expected volume

- **Minimum per business day:** 500 orders
- **Minimum on weekends:** 200 orders
- **Expected maximum (normal day):** 4,000 orders
- **Alert if below minimum:** Yes — may indicate ingestion failure
- **Alert if above maximum (normal day):** Yes — may indicate duplicates

### Uniqueness

- **Primary key:** `order_id`
- **Duplicates accepted:** No — dedup applied in Silver with log of discarded records
- **Note:** Source (ERP Tiny) has a known bug that occasionally generates duplicates. Resolved in Silver.

### Validity

| Rule | Expression | Action if violated |
|------|------------|--------------------|
| Non-negative revenue | order_amount_brl >= 0 | Alert + quarantine |
| Net revenue ≤ gross | net_revenue_brl <= order_amount_brl | Alert + investigation |
| Valid status | order_status IN ('pending', 'processing', 'completed', 'cancelled', 'refunded') | Alert |
| No future date | order_date <= CURRENT_DATE | Alert + quarantine |
| Valid channel | channel IN ('site', 'marketplace', 'app', 'telesales', 'b2b') | Alert |

### Consistency

- Sum of `net_revenue_brl` per month must have variance < 0.5% compared to the monthly ERP report
- Manual reconciliation performed by Finance at month-end

## Privacy Policy

- **Contains PII:** No (in this Gold dataset)
- **PII in source:** Yes — `customer_email`, `customer_cpf`, `customer_phone` exist in Bronze
- **Treatment applied:**
  - `customer_email`: hashed with SHA-256 in Silver (available as `customer_email_hash`)
  - `customer_cpf`: **removed** — not exposed in any analytical layer
  - `customer_phone`: **removed** — not exposed in any analytical layer
- **Who can access Bronze (with PII):** only Rafael Torres and Bruno Costa (IT)
- **Bronze retention:** 90 days, then automatically deleted
- **Silver/Gold retention:** 3 years, then permanently anonymized
- **Legal basis (LGPD):** Contract execution (Art. 7, V) + legitimate interest for business analysis (Art. 7, IX)
