## Detailed checklist

### IAM & Least Privilege
- [x] All service accounts follow least-privilege principle (no owner/editor roles)
  - `ingestion-sa`: `storage.objectCreator` on Bronze bucket + `secretAccessor`
  - `transformation-sa`: `storage.objectViewer` on Bronze + `bigquery.dataEditor` on silver/gold
  - `bi-sa`: `bigquery.dataViewer` on gold dataset only
  - `ci-sa`: Terraform apply scope + Dagster Cloud deploy — no data access
- [x] Bronze layer (`gs://sample-store-data/bronze/`) — accessible only to `ingestion-sa` (write) and `transformation-sa` (read). Uniform bucket-level access enforced.
- [x] Gold dataset — `bi-sa` and `data-analysts` group have `dataViewer` only. No direct analyst access to Silver or Bronze.
- [x] Human access to production BigQuery goes through the `data-analysts` IAM group (managed by Bruno Costa)
- [x] Offboarding process documented in `governance-policy.md` (Section: Access Management)

### Secrets & Credentials
- [x] No credentials in code — confirmed via `git grep` scan: no connection strings, passwords, or API keys found in repository
- [x] All secrets stored in GCP Secret Manager:
  - `erp-postgres-connection-string`
  - `google-sheets-sa-key`
  - `dagster-cloud-agent-token`
- [x] `dbt/profiles.yml` confirmed in `.gitignore` — not present in repository history
- [x] GitHub Actions uses a dedicated `ci-sa` key stored in GitHub Secrets (not in YAML files)
- [x] SA key rotation policy documented: every 90 days. Next rotation: 2024-07-05. Owner: Rafael Torres.

### Encryption
- [x] Encryption at rest: GCP default encryption active for GCS (Bronze) and BigQuery (Silver, Gold). Confirmed in GCP console.
- [x] Encryption in transit: all connections use TLS:
  - ERP PostgreSQL: `sslmode=require` confirmed in Dagster resource config
  - Google Sheets API: HTTPS enforced by Google
  - BigQuery API: HTTPS enforced by Google
  - Metabase → BigQuery: TLS enforced by BigQuery connector
- [x] PII column treatment confirmed (from data contract):
  - `customer_email`: SHA-256 hash in Silver — original not present in Silver or Gold
  - `customer_cpf`: removed in Silver — not present downstream
  - `customer_phone`: removed in Silver — not present downstream

### Network Isolation
- [x] GCS bucket: public access blocked at bucket level (uniform IAM, no ACLs)
- [x] BigQuery: no public datasets; all access via authenticated SA or user accounts
- [⚠️] Metabase VM: has a public IP (pre-existing setup). Private Google Access is enabled on the subnet — BigQuery traffic does not traverse the public internet. However, the Metabase UI port (3000) is protected only by firewall rule (allowed from company IP range). Full VPN/IAP migration is planned for Q3 2024.
- [x] No GCP services with unnecessary public IP created as part of this project (GCS, BigQuery, Dagster Cloud are all accessed via Google APIs)
- [x] Outbound connections from Dagster are limited to: ERP host (whitelisted), Google APIs (Sheets, GCS, BigQuery, Secret Manager)

### Audit Logging
- [x] BigQuery audit logging enabled on `silver` and `gold` datasets (DATA_READ, DATA_WRITE, DATA_ACCESS)
- [x] Log retention: 90 days in Cloud Logging
- [x] Pipeline logs reviewed — no PII in Dagster logs. Order IDs and batch counts only.
- [x] GCS access logs enabled on Bronze bucket
- [ ] Access anomaly alerting: **deferred** — Cloud Monitoring alert for unusual BigQuery reads will be configured in Q3 2024. Low priority given current team size.

### Compliance (LGPD)
- [x] All PII fields identified in `data-contract-orders.md` and `governance-policy.md`
- [x] PII treatment implemented and verified: `customer_cpf` and `customer_phone` not present in Silver or Gold
- [x] `customer_email` hashed (SHA-256) in Silver — original only in Bronze (restricted)
- [x] Bronze layer retention policy: 3 years, then deletion (documented in governance-policy)
- [x] Data residency: all data stored in GCP `us-east1` region — no cross-border transfer
